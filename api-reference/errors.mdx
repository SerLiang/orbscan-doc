Every response uses the same three fields: `message`, `status_code`, and `data`.

- On **success**: `status_code` is `"1"`, `message` is `"OK"`, and `data` holds the result.
- On **error**: `status_code` is `"0"`, `message` describes the problem, and `data` is `null`.

Use the **HTTP status code** to determine the type of error.

```json
{
  "message": "Missing or invalid API key",
  "status_code": "0",
  "data": null
}
```

## Status codes

| HTTP | `message` (example) | Cause & fix |
|---|---|---|
| `400` | `Invalid address format` / `Invalid txHash format` | A path or query value is malformed. This covers an `address` that isn't a valid `0x...` hex address, a `txHash` that isn't a 32-byte hex hash, and an order book `limit` outside its allowed range. |
| `401` | `Missing or invalid API key` | The API key is missing or wrong. Check the `Authorization: Bearer` header, or the `apikey` query parameter. |
| `403` | Varies | The API key is valid but not allowed to use this resource. Check your plan, or contact Orbscan. |
| `404` | `Not found` | The API endpoint does not exist. Check the path and spelling. A query that simply finds nothing returns `200` instead, as explained in [Empty results are not errors](#empty-results-are-not-errors). |
| `429` | `Rate limit exceeded` | You have sent too many requests. Wait for the limit window to reset, then retry with exponential backoff. See [Rate limits](/api-reference/rate-limits). |
| `500` | Varies | Something failed on our side. Retry with backoff. |
| `503` | Varies | A dependent service is temporarily unavailable. For example, order book coverage may have no cached value to return. Retry shortly. |

## Empty results are not errors

A valid request that finds nothing is not an error: it still succeeds with HTTP `200` and `status_code` `"1"`. The shape of `data` depends on the endpoint:

- **List endpoints** (activity, deposits & withdrawals, positions, rewards) return an empty `items` array:

```json
{
  "message": "OK",
  "status_code": "1",
  "data": { "items": [], "nextCursor": null }
}
```

- **Single-object endpoints** (for example [Get Actions by Hash](/api-reference/endpoints/get-transaction)) return `data: null`:

```json
{
  "message": "OK",
  "status_code": "1",
  "data": null
}
```

<Warning>
  Don't treat a `200` with empty `data` as a failure. An empty `items` array or a `null` `data` means "no results," not "error."
</Warning>

## Handling errors in code

<CodeGroup>

```python Python
import requests

resp = requests.get(url, timeout=30)
body = resp.json()

if body["status_code"] != "1":
    raise RuntimeError(f"Orbscan error {resp.status_code}: {body['message']}")

data = body["data"]
empty_list = isinstance(data, dict) and data.get("items") == []
if data is None or empty_list:
    print("No results")
else:
    print(data)
```

```javascript JavaScript
const resp = await fetch(url);
const body = await resp.json();

if (body.status_code !== "1") {
  throw new Error(`Orbscan error ${resp.status}: ${body.message}`);
}

const { data } = body;
if (!data || (Array.isArray(data.items) && data.items.length === 0)) {
  console.log("No results");
} else {
  console.log(data);
}
```

</CodeGroup>
