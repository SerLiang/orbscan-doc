The Orbscan API applies limits per API credential. Your exact limits may depend on your access agreement and production configuration. Contact Orbscan if you need the limits for your credential.

<Note>
  A rate-limited request returns HTTP `429` with `message: "Rate limit exceeded"`, `status_code: "0"`, and `data: null`.
</Note>

## Handling 429 responses

When you receive a `429` response, wait before trying again. Use exponential backoff and cap the number of retries. If repeated retries still return `429`, stop and wait longer rather than continuing to send requests.

<CodeGroup>

```python Python
import time
import requests

def get_with_rate_limit_handling(url, headers, max_retries=3):
    wait = 5
    for attempt in range(max_retries):
        response = requests.get(url, headers=headers)
        if response.status_code == 429:
            print(f"Rate limited. Retrying in {wait}s...")
            time.sleep(wait)
            wait *= 2
            continue
        return response
    raise RuntimeError("Exceeded max retries due to rate limiting")
```

```javascript JavaScript
async function getWithRateLimitHandling(url, headers, maxRetries = 3) {
  let wait = 5000;
  for (let attempt = 0; attempt < maxRetries; attempt++) {
    const response = await fetch(url, { headers });
    if (response.status === 429) {
      console.log(`Rate limited. Retrying in ${wait / 1000}s...`);
      await new Promise((resolve) => setTimeout(resolve, wait));
      wait *= 2;
      continue;
    }
    return response;
  }
  throw new Error("Exceeded max retries due to rate limiting");
}
```

## Best practices

These practices reduce unnecessary requests:

- **Cache infrequently changing data.** Market names, descriptions, and outcomes rarely change. Cache them locally and reserve requests for time-sensitive data.

- **Paginate, don't dump.** Use the `limit` query parameter and the `nextCursor` cursor to fetch data in manageable pages rather than requesting the largest possible payload in a single call. This keeps individual responses fast and reduces the chance of timeouts.

- **Poll responsibly.** Choose a polling interval that matches your credential limits and freshness requirements.
