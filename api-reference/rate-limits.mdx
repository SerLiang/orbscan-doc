The Orbscan API enforces rate limits to ensure consistent, reliable performance for all users. Limits are applied on a rolling per-minute window and a rolling 24-hour daily quota. If your application exceeds either limit, the API returns a `429 Too Many Requests` response until the relevant window resets. Understanding your limits — and designing your integration around them — will help you avoid disruptions.

<Note>
  Rate limits are enforced per API key, not per IP address. If you run multiple services or environments, each should use its own API key so their usage is tracked independently.
</Note>

## Plan Tiers

Your rate limits depend on the plan your API key is associated with. The table below summarises the limits for each tier.

| Plan | Requests / min | Daily Quota |
|---|---|---|
| Free | 30 | 10,000 / day |
| Pro | 120 | 100,000 / day |
| Enterprise | Custom | Contact Orbscan |

To upgrade your plan or inquire about Enterprise pricing, contact the Orbscan team.

## Handling 429 Responses

When you receive a `429` response, do not immediately retry the request — you will receive another `429` until the window resets. Wait briefly and then retry with exponential backoff.

<CodeGroup>

```python Python
import time
import requests

def get_with_rate_limit_handling(url, headers, max_retries=3):
    wait = 5
    for attempt in range(max_retries):
        response = requests.get(url, headers=headers)
        if response.status_code == 429:
            print(f"Rate limited. Retrying in {wait}s...")
            time.sleep(wait)
            wait *= 2
            continue
        return response
    raise RuntimeError("Exceeded max retries due to rate limiting")
```

```javascript JavaScript
async function getWithRateLimitHandling(url, headers, maxRetries = 3) {
  let wait = 5000;
  for (let attempt = 0; attempt < maxRetries; attempt++) {
    const response = await fetch(url, { headers });
    if (response.status === 429) {
      console.log(`Rate limited. Retrying in ${wait / 1000}s...`);
      await new Promise((resolve) => setTimeout(resolve, wait));
      wait *= 2;
      continue;
    }
    return response;
  }
  throw new Error("Exceeded max retries due to rate limiting");
}
```

## Best Practices

Following these practices will help you stay within your limits and get the most out of your quota:

- **Cache infrequently changing data.** Market metadata — names, descriptions, outcomes — rarely changes. Cache it locally rather than fetching it on every request. Reserve your quota for time-sensitive data like prices and activity.

- **Paginate, don't dump.** Use the `limit` and `offset` query parameters to fetch data in manageable pages rather than requesting the largest possible payload in a single call. This keeps individual responses fast and reduces the chance of timeouts.

- **Poll responsibly.** If you're building a real-time feed, poll at most once every 5 seconds. More frequent polling provides negligible freshness gains and burns through your rate limit quickly.
