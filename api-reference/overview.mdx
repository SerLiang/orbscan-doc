The Orbscan Open API is a REST API that returns JSON. It gives you programmatic access to on-chain Polymarket data: a wallet's trading activity, its deposits and withdrawals, and a decoded breakdown of any single transaction.

## Base URL

All requests go to:

```text
https://api.orbscan.com
```

Every endpoint path in this reference is relative to that base — for example, `GET /v1/trader/{address}/activity` means `https://api.orbscan.com/v1/trader/{address}/activity`.

## Authentication

Every request must include your API key as a **Bearer token** in the `Authorization` header. Requests without a valid key return `401`.

```bash
curl "https://api.orbscan.com/v1/trader/0x6a72f61820b26b1fe4d956e17b6dc2a1ea3033ee/activity?limit=1" \
  -H "Authorization: Bearer <your_api_key>"
```

See [Authentication](/api-reference/authentication) for full details and code samples.

<Warning>
  Your API key is a secret. Keep it server-side and never commit it to a public repository or expose it in client-side code.
</Warning>

## Response Format

Every response — success or error — uses the same envelope:

```json
{
  "message": "OK",
  "status_code": "1",
  "data": { }
}
```

| Field | Type | Description |
|---|---|---|
| `message` | string | `"OK"` on success, or a human-readable error description on failure. |
| `status_code` | string | `"1"` on success, `"0"` on error. Use the HTTP status code to identify the error type. |
| `data` | object / null | The requested payload. `null` when a request fails, or when a valid lookup simply has no result. |

<Note>
  A successful lookup that finds nothing still returns `200` with `status_code: "1"`. For list endpoints, `data.items` is an empty array. Check the shape of `data` rather than relying on the HTTP status alone.
</Note>

## Pagination

The list endpoints (activity, deposits & withdrawals) are cursor-paginated:

1. Request a page, optionally setting `limit` (default `50`, maximum `100`).
2. Read `data.nextCursor` from the response.
3. If it is **not** `null`, pass it back as the `cursor` query parameter to fetch the next page.
4. When `nextCursor` is `null`, you've reached the end.

```bash
# Page 1
curl "https://api.orbscan.com/v1/trader/{address}/activity?limit=50" \
  -H "Authorization: Bearer <your_api_key>"

# Page 2 — feed nextCursor back in
curl "https://api.orbscan.com/v1/trader/{address}/activity?limit=50&cursor=NEXT_CURSOR" \
  -H "Authorization: Bearer <your_api_key>"
```

## Available Endpoints

| Endpoint | Path | Description |
|---|---|---|
| [Get Trader Activity](/api-reference/endpoints/get-trader-activity) | `/v1/trader/{address}/activity` | Paginated buy, sell, and redeem history for a wallet |
| [Get Deposits & Withdrawals](/api-reference/endpoints/get-deposits-withdrawals) | `/v1/trader/{address}/deposits-withdrawals` | Combined USDC transfer history for a wallet |
| [Get Actions by Hash](/api-reference/endpoints/get-transaction) | `/v1/tx/{txHash}` | Decoded summary and fills for a single transaction |

<Tip>
  Prices in activity and transaction responses are expressed as **decimals** (0–1). A `price` of `"0.78"` means 78¢ per share.
</Tip>
